9Neural Networks from Scratch

≈ 1 hr 30 min · neurons, backpropagation, gradient descent
By the end: you can explain what a neuron computes, how a network learns from its mistakes, and why gradient descent works.

9.1 The neuron

A neuron takes inputs, multiplies each by a weight, adds a bias, then passes the result through an activation function.

z = w₁x₁ + w₂x₂ + … + wₙxₙ + b   →   a = f(z)
Inputs x→× weights w→+ bias b→Activation f→Output a
ActivationFormulaUse it for
Sigmoid1 / (1 + e⁻ᶻ)Binary output probability
Tanh(eᶻ − e⁻ᶻ)/(eᶻ + e⁻ᶻ)Zero-centred hidden units (older nets, RNNs)
ReLUmax(0, z)Default for hidden layers
Softmaxeᶻⁱ / Σ eᶻʲMulti-class output probabilities
Why activations matter: without a non-linear activation, stacking layers collapses into one linear function. Non-linearity is what lets depth add power.

9.2 Layers and the forward pass

Neurons are grouped into layers: input, one or more hidden layers, and an output layer. The forward pass pushes data through layer by layer to produce a prediction. A loss function (MSE for regression, cross-entropy for classification) measures how wrong that prediction is.

9.3 Gradient descent

Imagine standing on a foggy hill and stepping downhill. The gradient tells you the steepest uphill direction, so you move the opposite way.

w ← w − η · ∂L/∂w   (η = learning rate)

Live demo · Gradient descent on L(w) = (w − 3)²

w = -4.00   loss = 49.00   step # 0

Try η = 0.01 (crawls), 0.1 (smooth), 0.95 (zig-zags) and 1.05 (diverges).

9.4 Backpropagation

Backprop is the chain rule applied efficiently. It computes how much each weight contributed to the loss, working backwards from the output.

  1. Forward: compute activations layer by layer, store them.
  2. Loss: compare the prediction with the truth.
  3. Backward: compute ∂L/∂(output), then multiply by local derivatives layer by layer going backwards.
  4. Update: adjust every weight with gradient descent.
∂L/∂w₁ = ∂L/∂a · ∂a/∂z · ∂z/∂w₁

9.5 A network in about 20 lines of NumPy

import numpy as np
np.random.seed(0)
X = np.array([[0,0],[0,1],[1,0],[1,1]]); y = np.array([[0],[1],[1],[0]])  # XOR

W1, b1 = np.random.randn(2,4), np.zeros((1,4))
W2, b2 = np.random.randn(4,1), np.zeros((1,1))
sig = lambda z: 1/(1+np.exp(-z))

for epoch in range(10000):
    # forward
    h = np.tanh(X @ W1 + b1)
    p = sig(h @ W2 + b2)
    # backward
    dz2 = p - y                      # BCE + sigmoid shortcut
    dW2 = h.T @ dz2;  db2 = dz2.sum(0, keepdims=True)
    dz1 = (dz2 @ W2.T) * (1 - h**2)  # tanh derivative
    dW1 = X.T @ dz1;  db1 = dz1.sum(0, keepdims=True)
    # update
    for P, G in ((W1,dW1),(b1,db1),(W2,dW2),(b2,db2)): P -= 0.1 * G

print(p.round(2))   # ≈ [[0],[1],[1],[0]]
Why XOR? No single straight line separates XOR. A hidden layer solves it, which is the classic proof that depth matters.

9.6 Training practicalities

Optimisers
SGD, Momentum, Adam. Adam is the sensible default.
Batches & epochs
Mini-batches (32–256) give noisy but fast updates. One epoch = one pass over the data.
Overfitting fixes
Dropout, weight decay, early stopping, more data.
Vanishing gradients
Deep sigmoid/tanh stacks shrink gradients. ReLU, good initialisation and normalisation help.

10CNNs and Computer Vision

≈ 1 hr 15 min · convolution, pooling, architectures, transfer learning
By the end: you understand why images need convolutions instead of plain dense layers, and can fine-tune a pretrained vision model.

10.1 Why not a dense network?

A 224×224 RGB image has 150,528 inputs. A single dense layer of 1,000 units would need about 150 million weights, and it would ignore the fact that nearby pixels relate to each other. CNNs exploit two ideas: local connectivity and weight sharing.

10.2 The convolution operation

A small filter (kernel) slides across the image. At each position, multiply element-wise and sum. The same filter is reused everywhere, so it detects one pattern (an edge, a corner, a texture) wherever it appears.

10.6 Transfer learning: the practical shortcut

Rarely train from scratch. Start from a model pretrained on ImageNet, freeze the backbone, replace the final layer, train briefly, then optionally unfreeze and fine-tune with a small learning rate.

import torch.nn as nn
from torchvision import models

m = models.resnet18(weights="DEFAULT")
for p in m.parameters(): p.requires_grad = False   # freeze backbone
m.fc = nn.Linear(m.fc.in_features, num_classes)    # new head: train this only
Data augmentation: random flips, crops, rotations and colour jitter effectively multiply your dataset and reduce overfitting.

11RNNs, Sequences and NLP Basics

≈ 1 hr 15 min · text as numbers, recurrence, LSTM/GRU, embeddings
By the end: you can explain how text becomes numbers, how a recurrent network carries memory, and why its limits led to Transformers.

11.1 From text to numbers

  1. Tokenise: split text into words or sub-words. "unhappiness" → "un", "happi", "ness".
  2. Index: map each token to an integer ID.
  3. Embed: map each ID to a learned dense vector, so similar words sit close together.
ApproachCaptures meaning?Note
One-hot / Bag-of-wordsNoHuge sparse vectors, no order
TF-IDFWeaklyWeights rare, informative words; strong classical baseline
Word2Vec / GloVeYesOne fixed vector per word
Contextual (BERT, GPT)Yes, in contextSame word, different vector per sentence

11.2 The recurrent idea

Sequences have order and variable length. An RNN reads one step at a time and carries a hidden state, a running summary of everything seen so far.

hₜ = tanh(Wₓ·xₜ + Wₕ·hₜ₋₁ + b)
x₁→h₁→h₂ ← x₂→h₃ ← x₃→… → output

Training uses backpropagation through time: unroll the loop and backprop across every time step. Same weights are reused at each step.

The catch: multiplying gradients across many steps makes them vanish (or explode). A plain RNN forgets things from 20+ steps ago.

11.3 LSTM and GRU

Gated cells decide what to remember, forget and output, giving gradients a more direct path.

LSTM
Cell state plus three gates: forget, input, output. Powerful, more parameters.
GRU
Two gates: reset and update. Simpler, often similar accuracy, faster.

11.4 Common sequence tasks

PatternExample
Many → OneSentiment of a review, spam detection
Many → Many (aligned)Named entity tagging
Many → Many (seq2seq)Machine translation, summarisation
One → ManyCaption generation
import torch.nn as nn

class SentimentLSTM(nn.Module):
    def __init__(self, vocab, emb=128, hid=128):
        super().__init__()
        self.emb  = nn.Embedding(vocab, emb)
        self.lstm = nn.LSTM(emb, hid, batch_first=True)
        self.out  = nn.Linear(hid, 1)
    def forward(self, x):
        _, (h, _) = self.lstm(self.emb(x))   # h: last hidden state
        return self.out(h[-1])               # logit

11.5 Why we moved on

  • Strictly sequential: step t needs step t−1, so training can't be parallelised across time.
  • Long-range dependencies are still hard.
  • In seq2seq, squeezing a whole sentence into one vector is a bottleneck. Attention was invented to fix exactly that.

12Transformers and Attention

≈ 1 hr 30 min · self-attention, multi-head, architecture, LLMs
By the end: you can explain query/key/value attention, draw the Transformer block, and connect it to BERT and GPT-style models.

12.1 The core idea

Instead of reading word by word, let every token look at every other token at once and decide which ones matter. That is self-attention. In "The animal didn't cross the street because it was tired", attention lets "it" weigh "animal" heavily.

12.2 Queries, keys and values

Each token produces three vectors from learned projections:

  • Query (Q): what am I looking for?
  • Key (K): what do I offer?
  • Value (V): the information I pass along if selected.
Attention(Q, K, V) = softmax( QKᵀ / √dₖ ) · V
  1. Score: dot product of each query with every key.
  2. Scale by √dₖ to keep softmax stable.
  3. Softmax turns scores into weights summing to 1.
  4. Output is the weighted average of the values.

12.3 Multi-head attention and position

Multi-head
Run several attention operations in parallel, each in a smaller subspace. One head may track grammar, another coreference. Concatenate and project.
Positional encoding
Attention has no sense of order by itself, so position information (sinusoidal or learned) is added to the embeddings.

12.4 The Transformer block

Input + position→Multi-head attention→Add & Norm→Feed-forward→Add & Norm→× N layers

Residual connections (Add) and layer normalisation keep very deep stacks trainable, the same trick as ResNet.

RNNTransformer
Sequential, slow to trainFully parallel over the sequence
Memory fades over distanceAny token can attend to any other directly
Cost grows linearly with lengthAttention cost grows with length², the main scaling limit

12.5 Three families

TypeSeesExamplesBest at
Encoder-onlyWhole input, both directionsBERTClassification, search, embeddings
Decoder-onlyPast tokens only (causal mask)GPT family, Claude, LlamaText generation, chat
Encoder-decoderInput, then generates outputT5, original TransformerTranslation, summarisation

Decoder-only models generate by repeatedly predicting the next token. Pretraining on huge text corpora, followed by instruction tuning and human-feedback alignment, produces today's LLMs.
