4. Linear and Logistic Regression

≈ 75 min
By the end: you can explain how a model learns weights by minimising a loss, tell regression from classification, and read coefficients.

Linear regression: predict a number

Draw the best straight line (or plane) through the data. Each feature gets a weight; the prediction is a weighted sum plus a bias.

ŷ = w₁x₁ + w₂x₂ + … + wₙxₙ + b

How it learns: loss and gradient descent

MSE = (1/n) Σ (yᵢ − ŷᵢ)²
  1. Start with random weights.
  2. Compute predictions and the loss (MSE).
  3. Compute the gradient: which way increases the loss fastest?
  4. Step the opposite way: w ← w − α · ∇L (α = learning rate).
  5. Repeat until the loss stops improving.
Learning rate trap: too large and the loss bounces or explodes; too small and training crawls.

Regularisation: stop weights from getting greedy

MethodPenaltyEffect
Ridge (L2)λ Σ w²Shrinks all weights; good with correlated features
Lasso (L1)λ Σ |w|Pushes some weights to exactly 0, so it works as feature selection
Elastic NetBothBalance of the two

Logistic regression: predict a probability, then a class

Same weighted sum, but squashed through the sigmoid so the output lies between 0 and 1.

p = 1 / (1 + e−z) , z = w·x + b

Loss function: log loss (binary cross-entropy). It punishes confident wrong answers heavily.

L = −[ y·log(p) + (1−y)·log(1−p) ]
Despite the name, logistic regression is a classifier. Multi-class uses softmax (or one-vs-rest).

Reading coefficients

  • Linear: a weight of 3.2 means +1 unit of that feature raises the prediction by 3.2, others held fixed.
  • Logistic: weights act on log-odds; e^w is the odds ratio.
  • Scale features first, or weights are not comparable.

Assumptions and pitfalls

Linear regression assumes

  • Roughly linear relationship
  • Independent errors
  • Constant error variance
  • No severe multicollinearity

Watch out for

  • Outliers pulling the line
  • Extrapolating beyond the data range
  • Imbalanced classes in logistic regression

Hands-on

from sklearn.linear_model import LinearRegression, LogisticRegression, Ridge
from sklearn.pipeline import make_pipeline
from sklearn.preprocessing import StandardScaler

reg = make_pipeline(StandardScaler(), Ridge(alpha=1.0)).fit(X_train, y_train)
clf = make_pipeline(StandardScaler(), LogisticRegression(max_iter=1000)).fit(X_train, y_train)
print(clf.predict_proba(X_test)[:5])

Check yourself

Why can't we use MSE for logistic regression?With a sigmoid, MSE gives a non-convex loss surface with flat regions; log loss is convex and gives clean gradients.
Lasso vs Ridge: which can zero out a feature?Lasso (L1). Its diamond-shaped constraint has corners on the axes.

5. Decision Trees and Random Forests

≈ 75 min
By the end: you can explain how a tree chooses splits, why a single tree overfits, and how a forest fixes it.

Decision tree: a flowchart learned from data

How it picks the best split

At every node it tries splits and keeps the one that makes the child nodes purest.

Gini = 1 − Σ pₖ²   |   Entropy = − Σ pₖ log₂ pₖ

Information gain = impurity before split − weighted impurity after. For regression trees, the split minimises variance (MSE) instead.

Node mixGiniMeaning
100% one class0Pure
50 / 500.5Maximally mixed (binary)

The overfitting problem

Left unchecked, a tree keeps splitting until each leaf holds one training row: 100% train accuracy, poor test accuracy.

Controls: max_depth, min_samples_leaf, min_samples_split, ccp_alpha (cost-complexity pruning).

Random forest: many trees, one vote

  1. Bootstrap: each tree trains on a random sample of rows (with replacement).
  2. Feature subsampling: each split considers only a random subset of features.
  3. Aggregate: majority vote (classification) or average (regression).

Averaging many decorrelated, high-variance trees gives a low-variance model. This is bagging.

Free validation: rows left out of each bootstrap give the out-of-bag (OOB) score without a separate validation set.

Trees vs forests

Single treeRandom forest
InterpretabilityHigh (you can draw it)Low; use feature importance
OverfittingProneMuch more robust
Scaling needed?No for either; trees are scale-invariant
SpeedVery fastSlower, but parallelisable
Feature importance caveat: impurity-based importance favours high-cardinality features. Cross-check with permutation importance.

Hands-on

from sklearn.ensemble import RandomForestClassifier

rf = RandomForestClassifier(n_estimators=300, max_depth=None,
                            oob_score=True, n_jobs=-1, random_state=42)
rf.fit(X_train, y_train)
print("OOB:", rf.oob_score_, " Test:", rf.score(X_test, y_test))

Check yourself

Why does a forest use random feature subsets at each split?To decorrelate the trees. If every tree used the same strong feature at the top, their errors would be similar and averaging would help less.

6. SVM, KNN and Naive Bayes

≈ 75 min
By the end: you can describe the core idea of each algorithm and choose between them for a given dataset.

Support Vector Machine (SVM)

Find the decision boundary with the widest margin between classes. Only the closest points (support vectors) define it.

  • C parameter: small C allows a wider, softer margin (more errors tolerated); large C fits training data tightly.
  • Kernel trick: implicitly map data to a higher dimension so a curved boundary becomes linear. Common: linear, rbf, poly.
  • gamma (RBF): how far one point's influence reaches. High gamma means wiggly boundary and overfitting.
  • Must scale features.

K-Nearest Neighbours (KNN)

No training. To classify a new point, find the k closest training points and take a vote (or average for regression).

kBehaviour
Small (1–3)Flexible, noisy, overfits
LargeSmooth, may underfit
  • Distance metric matters: Euclidean, Manhattan, cosine.
  • Scale features, or the largest-range feature dominates.
  • Slow at prediction time on big data; suffers in high dimensions (curse of dimensionality).

Naive Bayes

Applies Bayes' theorem with a "naive" assumption: features are independent given the class.

P(class | x) ∝ P(class) · Π P(xᵢ | class)
  • GaussianNB: continuous features
  • MultinomialNB: word counts (text, spam filters)
  • BernoulliNB: binary features
The independence assumption is almost always false, yet Naive Bayes works surprisingly well for text and is extremely fast, a great baseline.

Laplace smoothing adds a small count so an unseen word never zeroes out the whole product.

Choosing between them

SVMKNNNaive Bayes
Best forMedium data, high dimensionsSmall data, quick baselineText, very fast baseline
Training speedSlow on large dataNoneVery fast
Prediction speedFastSlowVery fast
Scaling neededYesYesNot for count models
Key knobsC, kernel, gammak, metricsmoothing

Hands-on

from sklearn.svm import SVC
from sklearn.neighbors import KNeighborsClassifier
from sklearn.naive_bayes import GaussianNB
from sklearn.pipeline import make_pipeline
from sklearn.preprocessing import StandardScaler

models = {
  "SVM": make_pipeline(StandardScaler(), SVC(kernel="rbf", C=1, gamma="scale")),
  "KNN": make_pipeline(StandardScaler(), KNeighborsClassifier(n_neighbors=5)),
  "NB":  GaussianNB(),
}
for name, m in models.items():
    print(name, m.fit(X_train, y_train).score(X_test, y_test))

Check yourself

What happens to KNN if one feature is in the range 0–100000 and the others 0–1?That feature dominates the distance, so neighbours are chosen almost entirely by it. Scale the features.

7. Model Evaluation

≈ 90 min
By the end: you can pick the right metric, diagnose over/underfitting, and validate a model honestly.

Classification metrics

Everything starts from the confusion matrix:

Predicted +Predicted −
Actual +TPFN
Actual −FPTN
MetricFormulaQuestion it answers
Accuracy(TP+TN) / allHow often is it right overall?
PrecisionTP / (TP+FP)Of predicted positives, how many are real?
RecallTP / (TP+FN)Of real positives, how many did we catch?
F12PR / (P+R)Balance of precision and recall
ROC-AUCArea under TPR vs FPRHow well does it rank positives above negatives?
Accuracy paradox: with 99% negatives, predicting "negative" for everyone scores 99% accuracy and is useless. Use precision, recall, F1 or PR-AUC on imbalanced data.

Favour recall when…

Missing a positive is costly: disease screening, fraud detection.

Favour precision when…

False alarms are costly: spam moving real mail, legal flags.

Moving the probability threshold trades one for the other.

Regression metrics

MetricNotes
MAEAverage absolute error; same units as target; robust to outliers
MSE / RMSEPenalises large errors more; RMSE is back in target units
R²Share of variance explained; 1 is perfect, 0 is no better than predicting the mean

Overfitting vs underfitting

SymptomDiagnosisFixes
Train bad, validation badUnderfitting (high bias)More features, bigger model, less regularisation
Train great, validation badOverfitting (high variance)More data, regularise, simpler model, early stopping, ensembling

Bias–variance trade-off

Expected error = Bias² + Variance + Irreducible noise
  • Bias: error from wrong assumptions (a straight line for curved data).
  • Variance: sensitivity to the particular training sample.
  • Simple models: high bias, low variance. Flexible models: the reverse. Goal: the best balance.

Cross-validation

A single train/test split can be lucky or unlucky. K-fold CV splits data into k parts, trains on k−1 and validates on the remaining one, rotating k times, then averages.

  • Stratified k-fold: keeps class proportions in each fold; use for classification.
  • Time series: never shuffle; use forward-chaining splits.
  • Grid / random search + CV tunes hyperparameters; keep a final untouched test set.
Data leakage: fit scalers, imputers and feature selectors inside each training fold (use a Pipeline), never on the full dataset first.

Hands-on

from sklearn.model_selection import cross_val_score, StratifiedKFold, GridSearchCV
from sklearn.metrics import classification_report
from sklearn.pipeline import make_pipeline
from sklearn.preprocessing import StandardScaler
from sklearn.svm import SVC

pipe = make_pipeline(StandardScaler(), SVC())
cv = StratifiedKFold(n_splits=5, shuffle=True, random_state=42)
print(cross_val_score(pipe, X, y, cv=cv, scoring="f1").mean())

grid = GridSearchCV(pipe, {"svc__C":[0.1,1,10], "svc__gamma":["scale",0.01]}, cv=cv, scoring="f1")
grid.fit(X_train, y_train)
print(classification_report(y_test, grid.predict(X_test)))

Check yourself

Train accuracy 99%, validation 72%. What is wrong and what do you try?Overfitting (high variance). Try more data, stronger regularisation, shallower trees or a simpler model, and check for leakage or a bad split.
Cancer screening model: which metric to prioritise?Recall, because missing a real case is the costly error. Watch precision to keep false alarms manageable.

8. Unsupervised Learning: Clustering and PCA

≈ 75 min
By the end: you can group unlabelled data with K-Means, reduce dimensions with PCA, and judge whether the result is any good.

Supervised vs unsupervised

No target column. The algorithm looks for structure on its own: groups, patterns, a simpler representation.

K-Means clustering

  1. Pick k and place k centroids randomly.
  2. Assign each point to its nearest centroid.
  3. Update each centroid to the mean of its points.
  4. Repeat 2–3 until assignments stop changing.
Limits: you must choose k; assumes round, similar-sized clusters; sensitive to scale and outliers; result depends on initialisation (use k-means++, the sklearn default).

Choosing k

  • Elbow method: plot inertia (within-cluster squared distance) against k; pick the bend.
  • Silhouette score: from −1 to 1; higher means tighter, better-separated clusters.
  • Business sense counts: how many segments can you act on?

Other clustering methods

MethodIdeaGood for
HierarchicalMerge closest clusters step by step; dendrogramSmall data, nested structure
DBSCANDense regions are clusters; sparse points are noiseArbitrary shapes, outlier detection, no k needed

PCA: Principal Component Analysis

Finds new axes (principal components) along which the data varies most, then keeps only the top few. It's a rotation plus truncation.

  1. Standardise features.
  2. Compute the covariance matrix.
  3. Find its eigenvectors (directions) and eigenvalues (variance along each).
  4. Keep the top components; project the data onto them.

Explained variance ratio tells you how much information each component keeps. A common rule: keep enough components for 90–95%.

Use PCA to

  • Compress many correlated features
  • Speed up models
  • Visualise data in 2D
  • Reduce noise

Be careful

  • Components are hard to interpret
  • Only captures linear structure
  • Always scale first
  • High variance does not always mean useful for prediction

For non-linear 2D visualisation, look at t-SNE or UMAP (visual only; not for feature engineering).

Hands-on

from sklearn.preprocessing import StandardScaler
from sklearn.cluster import KMeans
from sklearn.decomposition import PCA
from sklearn.metrics import silhouette_score

Xs = StandardScaler().fit_transform(X)

for k in range(2, 8):
    labels = KMeans(n_clusters=k, n_init=10, random_state=42).fit_predict(Xs)
    print(k, round(silhouette_score(Xs, labels), 3))

pca = PCA(n_components=0.95).fit(Xs)       # keep 95% variance
print(pca.n_components_, pca.explained_variance_ratio_.round(3))
X2 = PCA(n_components=2).fit_transform(Xs) # for plotting

Check yourself

Why must you scale data before K-Means or PCA?Both rely on distances/variance. Large-range features would dominate the clusters and the components.
Which clustering method finds outliers and arbitrary shapes?DBSCAN.

You now have a toolbox: linear/logistic (simple, interpretable), trees/forests (strong on tabular data), SVM/KNN/NB (specialised baselines), evaluation (how to trust any of them) and unsupervised (find structure without labels).
